# 2D 形象动作参考制作流程

本文档定义知令 2D 序列帧动作的**标准制作链路**，从一张基础帧出发，到可入库、可导入、可被大模型理解的动作资产为止。

> **路径说明**：文中出现的 `assets/whale_gril/...` 是维护者的历史素材工作区，**不随本仓库发布**；外部作者请将这些路径替换为自己的原画 / 视频目录。

目标产出：

- `assets/pet_seq/<avatar>/<action>/frame_###.webp`（768×1024 RGBA，12fps 基准）；
- 动作目录内的 `config.json`（动作元数据 + 逐帧时长倍数）；
- `assets/pet_seq/manifest.json` 中该动作的 `label` / `fps` / `loop` / `runtime` / **`description`** / `note`（与 config.json 同步）；
- 通过 `tools/pack_2d_frames.py --validate` 的资产包（可选发布）。

核心约定只有一条：

> **基础帧（base frame）同时作为视频的首帧和末帧。**
> 成品首尾都回到同一个姿态，循环播放时接缝不跳变，单次动作播完也能无缝回到 `idle`。
> 首尾各约 0.5 秒必须是**同一姿态的静止段**：不能首帧静止、末帧还在动，也不能首尾姿态差一个手势/角度。

## 0. 总览

```text
基础帧 base/frame_000.webp（正面全身站姿；视频首末帧用同姿态绿幕图）
        │
        ├─ 作为 first_frame ─┐
        └─ 作为 last_frame  ─┤
                             ▼
        Seedance 2.5 图生视频：4s / 720p / 9:16 / 无音频
                             │
                             ▼
        4s 绿幕视频（首尾各约 0.5s 保持基础帧姿态）
                             │
                             ▼
        seq_pipeline：解码 → 色键 → 选窗 → 循环接缝优化
                             │
                             ▼
        统一画布 768×1024 → WebP 入库 → 更新 manifest
                             │
                             ▼
        工作台预览 / 打包为资产包
```

对应工具：

| 阶段 | 工具 | 说明 |
|---|---|---|
| 基础帧 | `assets/pet_seq/<avatar>/base/frame_000.webp`；绿幕版由 `assets/whale_gril/chibi_seq/tools/make_first_frame.py` 生成 | 所有动作共用；原画见 `base/artwork.png` |
| 视频生成 | Seedance 2.5（图生视频 / 首尾帧） | 4 秒、720p、9:16、无音频 |

| 预览编辑 | `tools/seq_asset_tool/start.bat` | 逐帧预览、插删帧、逐帧时长、动作描述 |
| 校验打包 | `tools/pack_2d_frames.py` | 与知令导入器同口径校验 |

## 1. 准备基础帧

### 1.1 基础帧的硬性要求

基础帧不是“随便一张立绘”，它是整个动作的零姿态，所有帧都以它为参照：

| 项目 | 要求 |
|---|---|
| 姿态 | 正面全身站姿，双臂自然下垂，双脚并拢或与肩同宽，表情中性 |
| 构图 | 角色完整在画面内，头顶与画面顶部留出动作空间，脚底下方留少量绿幕 |
| 机位 | 正面平视，不俯不仰，不透视变形 |
| 背景 | 纯平 `#00FF00` 绿幕，无渐变、无阴影、无地面、无文字、无水印 |
| 比例 | 与视频输出一致，推荐 9:16（720×1280） |
| 一致性 | 后续所有动作共用同一张基础帧，不因动作重绘服装/发型/配色 |

> 基础帧同时承担三个角色：视频首帧、视频末帧、抽帧后的姿态参照（`headHold` / `tailHold`）。
> 它一旦变更，已有动作的首尾对齐关系全部失效，应整批重做。

规范资产库中，每个形象必须把基础帧与原画放在形象根目录的 `base/`：

```text
assets/pet_seq/whale_chibi/base/
├── frame_000.webp   # 768×1024 RGBA，透明底，与动作帧同规格；所有动作的首尾参照
├── artwork.png      # 1024×1024 原画，白底；只作设定参考，不参与播放与打包
└── README.md
```

- `base/frame_000.webp` 应与 `idle/frame_000.webp` 保持一致；
- 生成 Seedance 首/末帧时使用同一张基础姿态的绿幕版（720×1280），由 `make_first_frame.py` 从原画派生；
- `base/` 只作作者侧参考，不会进入用户资产包，避免把参考素材混进播放资源。

### 1.2 从标准立绘生成基础帧

以鲸鱼娘为例：

```bash
cd assets/whale_gril/chibi_seq
python tools/make_first_frame.py
# 可调参数：
# python tools/make_first_frame.py --canvas 720x1280 --width-ratio 0.917 --foot-y 1150
```

脚本会：

1. 对 `source/C17_keyed_green.png` 做色键，取最大连通域作为角色；
2. 按画布宽度比例等比缩放（默认占宽 91.7%）；
3. 水平居中、脚底对齐到 `y=1150`（底部留 130px 绿幕）；
4. 输出 `source/C17_first_frame.png`（720×1280 绿幕 RGB）与 `source/C17_stand.png`（透明 RGBA 参考）。

### 1.3 基础帧自检

- [ ] 角色左右对称、没有倾斜；
- [ ] 脚底在同一水平线，尾巴不压到画面边缘；
- [ ] 绿幕颜色均匀，角色边缘无明显绿边；
- [ ] 角色高度约占画面 78%–88%，上方至少留 80px 动作空间；
- [ ] 与上一版基础帧对比：若姿态/大小变化，需重做全部动作。

## 2. 用 Seedance 2.5 生成 4 秒绿幕视频

### 2.1 模型与参数

| 参数 | 取值 | 说明 |
|---|---|---|
| 模型 | `seedance-2.5/image-to-video`（图生视频） | 支持首帧 + 末帧控制 |
| 首帧 | 基础帧 `base.png` | `first_frame_url` / 首帧图片 |
| 末帧 | **同一张基础帧** `base.png` | `last_frame_url` / 尾帧图片 |
| 时长 | `4` 秒 | 图生视频支持 4–30 秒，4 秒是最短档 |
| 分辨率 | `720p` | 抽帧后统一到 768×1024，720p 足够；需要更细腻时可 1080p |
| 画幅 | 跟随首帧（9:16） | 不要二次裁切，避免角色比例变化 |
| 音频 | 关闭 | 序列帧不需要音轨 |
| 镜头 | 固定机位 | 若接口支持 `camera_fixed`，设为 true |
| 尾帧返回 | 可选 `return_last_frame` | 用于核对末帧是否真的回到基础帧 |

> 不同服务商的字段名可能略有差异（`first_frame_url` / `last_frame_url`、`image` / `last_image` 等），
> 但**语义必须是“首帧和末帧都传同一张基础帧”**。只传首帧、靠提示词让模型自己回位，属于降级方案，
> 末帧漂移风险明显更高，只在模型不支持末帧时使用。

### 2.2 固定 Prompt 模板

每个动作都使用同一段固定前缀，只替换最后的「动作」段：

```text
以首帧图中的<角色名>为唯一角色，严格保持角色设计完全一致：<发型、发饰、服装、配饰、尾巴等固定特征>。
固定机位正面全身拍摄，角色始终完整留在画面中，位置与大小全程不变，镜头不推拉、不旋转、不晃动。
背景必须是完全纯平的亮绿色 #00FF00 纯色幕布：无渐变、无阴影、无地面、无场景、无文字、无水印、无其他角色、无粒子特效。
时间结构（总长 4 秒）：开头 0.5 秒保持首帧的正面站立姿态几乎静止；随后 3 秒完成动作；
最后 0.5 秒回到与开头完全相同的站姿并保持静止。首帧与末帧必须是同一姿态。
只改变姿态，不改变角色外观与配色。
动作：<动作段>
```

动作段写法：

```text
<哪个部位> + <做什么动作> + <幅度/次数/节奏> + <其他部位保持什么状态> + <表情>
```

示例（挥手）：

```text
动作：右手从身侧抬起到肩高，手掌张开左右挥动两次，然后放回身侧；左手自然下垂，双脚不动，保持微笑。
```

### 2.3 动作设计约束

为了保证 4 秒内可完成、首尾可对齐、抽帧后不糊：

- **一个主运动**：一次只做一个主要动作（挥手、鞠躬、鼓掌……），最多加一个次级运动（尾巴/头发轻摆）；
- **不做位移**：不走路、不转身、不跳离地面（“原地轻跳”允许，但脚必须回到原位）；
- **不换手、不遮挡脸部**：除 `shy`（捂脸）、`think`（托下巴）等设计需要的短时遮挡；
- **幅度可控**：手臂不超出画面，尾巴不扫出边界，角色不缩放；
- **循环动作事件次数固定**：`idle` 只眨一次眼，`sleepy` 只点一次头；避免 4 秒内发生 2–3 次导致循环节奏错乱；
- **单次动作必须回位**：动作在 3 秒内完成，最后 0.5 秒回到基础帧姿态；
- **一条视频只做一个动作**：不要一条 4 秒视频里切两个动作，抽帧窗口无法同时对齐两个动作的首尾。

### 2.4 生成后先验片

在抽帧前，用播放器逐项检查：

- [ ] 第 0 帧与最后一帧是否与基础帧姿态一致（可叠加对比）；
- [ ] 角色是否全程完整、没有出画、没有缩放/漂移；
- [ ] 背景是否纯绿、没有阴影/渐变/地面；
- [ ] 动作是否在 0.5s–3.5s 内完成，首尾各有约 0.5s 静止；
- [ ] 手指、发梢、尾巴边缘有没有明显绿边或糊化；
- [ ] 循环动作是否只发生一次关键事件（眨眼/点头）。

不合格就重生成，不要指望后期抽帧能修复姿态漂移。

## 3. 抽帧、选窗与入库

### 3.1 一条命令

```bat
cd tools\seq_asset_tool

REM 先预览，不写资产库
run_pipeline.bat --video ..\..\assets\whale_gril\chibi_seq\video\wave.mp4 ^
  --avatar whale_chibi --action wave --no-loop --frames 36 ^
  --dry-run --preview-dir .tmp_wave_preview

REM 确认后正式入库
run_pipeline.bat --video ..\..\assets\whale_gril\chibi_seq\video\wave.mp4 ^
  --avatar whale_chibi --action wave --no-loop --frames 36
```

循环动作把 `--no-loop` 换成 `--loop`：

```bat
run_pipeline.bat --video ..\..\assets\whale_gril\chibi_seq\video\idle.mp4 ^
  --avatar whale_chibi --action idle --loop --frames 36
```

也可以在工作台里操作：右侧「动作」→「导入绿幕视频…」，选择新建/替换、帧数、帧率、循环，
高级参数里可调画布、选窗与 WebP 质量。

### 3.2 4 秒如何变成 36 帧

- 视频按目标帧率 `12fps` 解码，4 秒约 **48 帧**；
- 取 **36 帧**（3 秒）作为动作窗口，对应 12fps 下 3 秒；
- 选窗算法在 48 帧中滑动 36 帧窗口，按以下项评分：
  - `headHold`：窗口前 4–6 帧与基础帧的相似度（开头是否还在站姿）；
  - `tailHold`：窗口后 4–6 帧与基础帧的相似度（结尾是否回到站姿）；
  - `motion`：窗口内轮廓变化 + 画面变化（确保选到动作段，不是静止 hold）；
  - `jitter` / `cropPenalty`：头部与脚底抖动、角色触边惩罚；
  - `loop` 动作额外看首尾相似度、接缝运动量 `seamRatio` 与速度连续性。
- 循环动作在渲染后还会再量一次接缝：若接缝明显比正常帧间运动更小（首尾几乎重复），
  自动去掉第一帧或最后一帧，避免循环时停顿一帧（`trim_rendered_loop`，阈值 0.72）；
- 单次动作优先选动作段，并尽量让结尾回到基础帧姿态。

> 经验：如果自动窗口总是选偏，先用 `--window-start <0-based 帧号>` 手动指定。
> 12fps 下 1 秒 = 12 帧，动作通常从第 6 帧（0.5s）开始。

### 3.3 流水线自动做的画面处理

| 步骤 | 处理 |
|---|---|
| 色键 | `G - max(R,B)` 软阈值 alpha，形态学开闭运算，连通域过滤，去绿溢 |
| 缩放 | 预乘 alpha 缩放，避免透明区绿色插值进角色边缘 |
| 画布 | 统一 `768×1024`，脚底基准 `y=980`，角色目标高度上限 `800px`，左右边距 `24px` |
| 去抖 | 头部中心 x / 脚底 y 中值趋势对齐，水平趋势位移上限 `8px` |
| 编码 | WebP，质量 `82`，method `4` |
| 备份 | 旧动作整组移入 `assets/pet_seq/.trash/<时间戳>/<形象>/<动作>`，不物理删除 |

### 3.4 入库后的文件

```text
assets/pet_seq/whale_chibi/wave/
├── frame_000.webp
├── frame_001.webp
├── ...
├── frame_035.webp
└── config.json          # 动作元数据 + 逐帧时长；流水线在帧数不变时会保留原配置
```

`config.json` 同时承载动作语义（`label` / `description` / `fps` / `loop` / `note`）与
逐帧时长（`baseFps` + `frameMultipliers`）；`manifest.json` 保留库级索引，工具写入时同步两者。

## 4. 动作元数据：一个 config.json 管全

### 4.1 `config.json`：动作语义 + 每一帧停留多久

```json
{
  "schemaVersion": 1,
  "id": "wave",
  "label": "挥手",
  "description": "挥手：右手从身侧抬到肩高，手掌张开左右挥动两次后放回身侧；左手自然下垂，双脚不动；首尾均为正面站姿，保持微笑。",
  "fps": 12,
  "loop": false,
  "note": "右手抬起至肩高，左右挥动两次后回落；播放一次后回 idle。",
  "baseFps": 12,
  "frameMultipliers": {
    "frame_004.webp": 2,
    "frame_005.webp": 1.5
  },
  "updatedAt": "2026-10-21T08:00:00.000Z"
}
```

- `label` / `description` / `fps` / `loop` / `note` 是动作元数据，与 `manifest.json` 的
  `actions[]` 同口径；工具写入时两边同步，读取时以 `config.json` 为准。
- `frameMultipliers` 只记录非 1 的覆盖项；实际单帧停留 = `1000 / baseFps × 倍数`；
- 未列出的帧按 1 倍；倍数范围 0.1–20；
- 适合做“动作中段慢一点、回位快一点”的节奏微调；
- 不改变帧数。旧版 `timing.json` 仍可读取，但新动作必须写 `config.json`。

### 4.2 `description`：这个动作整体在做什么

`description` 是**面向大模型与 UI 的动作语义描述**，回答“这个动作是什么、身体怎么动、节奏如何、
首尾是什么姿态”。它与 `label`（短名）、`note`（制作备注）分工不同：

| 字段 | 面向 | 内容 | 示例 |
|---|---|---|---|
| `label` | UI 按钮 | 2–4 字短名 | `挥手` |
| `description` | 大模型 / 动作选择 / 播报 | 一句完整动作说明，建议 30–80 字 | `右手从身侧抬到肩高，手掌张开左右挥动两次后放回；左手自然下垂，双脚不动，首尾均为正面站姿。` |
| `note` | 制作/维护 | 来源视频、参数、待办 | `由绿幕视频生成：wave.mp4；36 帧 @ 12fps。` |

写法建议（四段式，便于模型稳定理解）：

```text
<动作意图>：<主要部位 + 运动>；<幅度/次数/节奏>；<其他部位状态>；<首尾姿态>。
```

示例：

```json
{
  "id": "idle",
  "label": "待机",
  "description": "待机循环：身体随呼吸轻微起伏，只眨一次眼，侧发与鲸鱼尾巴轻摆；幅度小、节奏慢；双臂自然下垂，首尾均为正面站姿。",
  "fps": 12,
  "loop": true,
  "runtime": true
}
```

约束：

- 可选字段；缺失或空串不影响导入与播放；
- 单行文本，去除首尾空白，建议 ≤ 200 码点（超出由工具截断）；
- 不写“尚未生成帧”“待重做”等制作状态（那属于 `note`）；
- 不写与画面不符的内容；描述必须和实际帧一致，否则会误导大模型选动作；
- 循环动作在描述里点明“循环”与首尾姿态；单次动作点明“播放一次后回到站姿”。

> 资产包规范中该字段的定义见 [asset-pack-spec.md](asset-pack-spec.md) 的 `actions[]` 与 `config.json` 字段表。
> 制作时写入动作目录 `config.json`，并同步到包内 `manifest.json`；知令导入器会保留两者供运行时/工具读取。

## 5. 质检清单（入库前）

### 5.1 画面

- [ ] 36 帧（或预期帧数），命名 `frame_000.webp` 起连续；
- [ ] 每帧 768×1024 RGBA，脚底位置稳定（±2px）；
- [ ] 角色不触边，头部/手部/尾巴没有被裁切；
- [ ] 边缘无绿边、无半透明黑边；
- [ ] 动作完整可辨识，不是只动了一两帧。

### 5.2 首尾对齐（重点）

- [ ] 第 0 帧与最后一帧姿态接近基础帧；
- [ ] 循环动作：首帧→末帧→首帧播放无跳变、无停顿；
- [ ] 单次动作：末帧回到站姿，接 `idle` 不突兀；
- [ ] 查看流水线输出的 `loopIoU` / `seamRatio`：`seamRatio` 越接近 1 越好；
      经验上 0.7–1.3 较稳，流水线在 `< 0.5` 或 `> 1.8` 时会给警告；
- [ ] 首尾对齐不能只靠“裁掉几帧”：如果姿态本身没回位，应重新生成视频。

### 5.3 元数据

- [ ] `label`、`description`、`fps`、`loop` 与实际一致；
- [ ] `description` 能被大模型直接读懂（不依赖上下文）；
- [ ] `note` 记录了来源视频与生成参数，便于复现；
- [ ] 循环动作 `loop=true`，单次动作 `loop=false`。

- 逐帧查看首尾帧，确认接缝；

## 7. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 循环时停顿一帧 | 首尾帧几乎相同，或末帧重复了首帧 | 用 `--loop` 让流水线裁掉重复定格；仍明显则缩短 `--frames` 或重生成 |
| 循环时跳变 | 末帧没回到基础帧，或角色位置/大小漂移 | 检查是否真的把基础帧传给了 `last_frame`；重生成，不要靠裁帧硬修 |
| 动作只做了一半 | 4 秒内动作设计过大 | 拆分动作或降低幅度；单次动作控制在 3 秒内完成 |
| 角色越做越小/越大 | 模型推拉镜头 | prompt 强调“固定机位、位置与大小不变”；换 seed/重生成 |
| 边缘绿边 | 色键阈值或压缩导致 | 检查原视频绿幕是否纯平；流水线已做去绿溢，仍明显则提高素材质量 |
| 角色被裁切 | 动作幅度超出画面 | 基础帧留足上方空间；缩小动作幅度或改用更宽画布 |
| 首尾帧姿态对不上 | 只传了首帧，末帧由模型自由发挥 | 使用首尾帧接口，首末帧都传基础帧 |
| 动作描述与画面对不上 | 先写描述后改动作，未同步 | 以最终帧为准回写 `description`，再入库 |
